## 为什么用 Astro

本站只需要展示内容，不需要登录、不需要数据库、不需要后端接口。
这类站点最适合**静态生成**：构建时把页面编译成 HTML，访问时直接返回文件。

Astro 的取舍很合这个场景：

- 默认输出零 JavaScript，页面里没有客户端框架运行时
- 组件写法接近原生 HTML，不需要先学一套模板语法
- 需要交互的地方（比如深浅色切换）可以单独加脚本，不影响其他页面

代价是构建工具链偏重。为了两个页面装两百多兆依赖，从资源占用上看并不划算；
但考虑到后面还要持续写文章，这个一次性成本可以接受。

## 配色

配色取自 [Catppuccin](https://catppuccin.com/)，浅色用 Latte，深色用 Mocha。
两套同族，切换时观感一致。

配色定义集中在 `src/styles/theme.css`，只改色值不动结构：

```css title="src/styles/theme.css"
:root,
[data-theme="light"] {
  --background: #eff1f5;
  --foreground: #4c4f69;
  --accent: #8839ef;
}

[data-theme="dark"] {
  --background: #1e1e2e;
  --foreground: #cdd6f4;
  --accent: #f38ba8;
}
```

> [!NOTE]
> 改配色时记得成对改 —— 浅色和深色两个块都要动，
> 否则会出现某一套主题下文字看不清的情况。

## 中文排版

英文排版的默认参数直接用在中文上会偏挤。这里做了两处调整：

1. 正文行高放大到 `1.9`（英文默认值约 `1.75`）
2. 段间距加大，避免密排

字体上，拉丁字母用 JetBrains Mono 保留等宽观感，中文回退系统黑体：

```css
--font-cjk: "PingFang SC", "Microsoft YaHei", sans-serif;
--font-app-stack: var(--font-mono-stack), var(--font-cjk);
```

> [!IMPORTANT]
> 等宽字体基本都不含中文字形，强行给中文套等宽会让字形变挤。
> 分开处理是更实际的做法。

## 踩过的坑

**时区。** 只写日期（`2026-09-27`）会被解析成 UTC 零点，
在东八区显示出来就变成前一天。所以 frontmatter 里的时间要求写全：

```yaml
# 会算错
pubDatetime: 2026-09-27

# 正确
pubDatetime: 2026-09-27T10:00:00+08:00
```

**透明度会吃掉对比度。** 用 `opacity-70` 淡化文字很方便，
但它会把颜色按比例混向背景 —— 原本达标的前景色可能因此掉到 4.5:1 以下。
改用专门的次要文字色更稳妥。

## 小结

选型和配色都是可以随时调整的，真正需要一开始就定对的是**内容结构** ——
URL 一旦发布出去就尽量别改。所以本站的文章链接取自文件名：
改标题不影响链接，避免外部引用失效。
